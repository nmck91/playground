## Overview

The CI/CD pipeline automatically runs on every push and pull request to ensure code quality, test coverage, and prevent regressions.

### Pipeline Architecture

```
┌─────────────────┐
│  Push to main   │
│  or PR created  │
└────────┬────────┘
         │
         v
┌────────────────────────────────────────┐
│         Main CI Workflow               │
├────────────────────────────────────────┤
│ 1. Checkout code                       │
│ 2. Setup Node.js (v22)                 │
│ 3. Install dependencies (npm ci)       │
│ 4. Build all projects          [GATE] │
│ 5. Lint all projects           [GATE] │
│ 6. Test engine with coverage   [GATE] │
│ 7. Validate coverage           [GATE] │
│ 8. Test app                    [GATE] │
│ 9. Test other projects         [GATE] │
│ 10. Upload coverage to Codecov         │
│ 11. Archive artifacts                  │
└────────┬───────────────────────────────┘
         │
         ├──> If PR: Trigger PR Comment
         │    └──> Post coverage report
         │
         └──> If main: Merge to release
              └──> Auto-merge passing code
```

## Workflows

### 1. Main CI Workflow

**File**: `.github/workflows/ci.yml`

**Triggers:**
- Push to `main` branch
- Pull requests to any branch

**Jobs:**

#### Job: Build, Test & Lint

```yaml
steps:
  # Setup
  - Checkout code (with full history)
  - Setup Node.js 22 with npm caching
  - Upgrade npm to v11
  - Install dependencies (npm ci)
  - Install Playwright browsers
  - Reset Nx cache

  # Quality Gates (all required to pass)
  - Build all projects
  - Lint all projects
  - Test football-director-engine (with coverage)
  - Check coverage thresholds
  - Test football-director app
  - Test all other projects

  # Reporting
  - Upload coverage to Codecov
  - Archive coverage reports (30 days)
  - Archive test results (30 days)
```

**Exit Codes:**
- `0` - All checks passed ✅
- `1` - Build failed ❌
- `1` - Lint failed ❌
- `1` - Tests failed ❌
- `1` - Coverage below threshold ❌

#### Job: Merge to Release

**Triggers**: After main CI passes, only on `main` branch pushes

```yaml
steps:
  - Checkout code with full history
  - Configure Git (GitHub Actions Bot)
  - Fetch release branch
  - Merge main to release (fast-forward only)
  - Push to release branch
```

### 2. PR Comment Workflow

**File**: `.github/workflows/pr-comment.yml`

**Triggers:**
- After CI workflow completes successfully
- Only for pull requests

**Process:**

```yaml
steps:
  # Download coverage from CI run
  - Download coverage artifacts

  # Parse coverage metrics
  - Extract lines, branches, functions percentages
  - Calculate status indicators (🟢/🟡/🔴)

  # Post/update PR comment
  - Find existing coverage comment
  - Update if exists, create if not
  - Include coverage table and thresholds
```

**Example Comment:**

```markdown
## 📊 Coverage Report

### football-director-engine
| Metric | Coverage | Status |
|--------|----------|--------|
| Lines | 93.21% | 🟢 |
| Branches | 83.15% | 🟢 |
| Functions | 94.85% | 🟢 |

### Thresholds
- 🟢 ≥ 90% (Excellent)
- 🟡 ≥ 80% (Good)
- 🔴 < 80% (Needs Improvement)

---
*Coverage report generated by CI*
```

## Quality Gates

All quality gates must pass before code can be merged to main.

### Gate 1: Build

**Command**: `npx nx run-many -t build`

**Purpose**: Ensure all TypeScript compiles without errors

**Common Failures:**
- Type errors
- Missing dependencies
- Import path errors
- Circular dependencies

**Fix:**
```bash
# Run locally
npx nx run-many -t build

# Check specific project
npx nx build <project-name>

# View detailed errors
npx nx build <project-name> --verbose
```

### Gate 2: Lint

**Command**: `npx nx run-many -t lint`

**Purpose**: Enforce code quality and style standards

**Common Failures:**
- Unused variables
- Missing type annotations
- Formatting issues
- ESLint rule violations

**Fix:**
```bash
# Auto-fix most issues
npx nx run-many -t lint --fix

# Check specific project
npx nx lint <project-name>

# Manual fixes for complex issues
npx nx lint <project-name> --verbose
```

### Gate 3: Engine Tests

**Command**: `npx nx test football-director-engine --coverage --run`

**Purpose**: Verify core game engine functionality

**Success Criteria:**
- All 791+ tests pass
- No runtime errors
- Coverage report generated

**Common Failures:**
- Test logic errors
- Mock configuration issues
- Async timing problems

**Fix:**
```bash
# Run locally with coverage
npx nx test football-director-engine --coverage

# Run specific test file
npx nx test football-director-engine -- <filename>

# Debug mode
npx nx test football-director-engine -- -t "test name"
```

### Gate 4: Coverage Validation

**Command**: `node .github/scripts/check-coverage.js "football-director-engine" "coverage/libs/football-director-engine"`

**Purpose**: Ensure code coverage meets quality thresholds

**Thresholds:**
```javascript
{
  global: {
    lines: 80%,      // ✅ Current: 93.21%
    branches: 70%,   // ✅ Current: 83.15%
    functions: 80%,  // ✅ Current: 94.85%
    statements: 80%, // ✅ Current: 91.9%
  },
  perFile: {
    lines: 60%,      // Minimum per-file coverage
  },
}
```

**Output:**
```
📊 Checking coverage for football-director-engine...

📈 Coverage Summary:
  Lines:      93.21%
  Branches:   83.15%
  Functions:  94.85%
  Statements: 91.9%

✅ football-director-engine coverage meets all thresholds!

⚠️  1 file(s) below 60% line coverage:
  0.00% - /libs/football-director-engine/src/lib/types.ts
```

**Common Failures:**
- New code without tests
- Removed tests without removing code
- Edge cases not covered
- Error handling not tested

**Fix:**
```bash
# Generate coverage report
npx nx test football-director-engine --coverage

# View HTML report to find gaps
open coverage/libs/football-director-engine/index.html

# Add tests for uncovered lines
# Re-validate
node .github/scripts/check-coverage.js "football-director-engine" "coverage/libs/football-director-engine"
```

### Gate 5: App Tests

**Command**: `npx nx test football-director --run`

**Purpose**: Verify React app functionality and store orchestration

**Success Criteria:**
- All integration tests pass
- All store tests pass
- All component tests pass

**Fix:**
```bash
# Run locally
npx nx test football-director

# Run specific test suite
npx nx test football-director -- orchestration.integration.test.ts

# Watch mode for debugging
npx nx test football-director --watch
```

### Gate 6: Other Projects

**Command**: `npx nx run-many -t test --exclude=football-director,football-director-engine --run`

**Purpose**: Ensure all other projects pass tests

**Fix:**
```bash
# Run all project tests
npx nx run-many -t test

# Run specific project
npx nx test <project-name>
```

## Coverage Validation

### Automated Validation

The coverage validation script runs automatically in CI after tests complete.

**Script**: `.github/scripts/check-coverage.js`

**Usage:**
```bash
node .github/scripts/check-coverage.js <project-name> <coverage-path>

# Example
node .github/scripts/check-coverage.js "football-director-engine" "coverage/libs/football-director-engine"
```

**Exit Codes:**
- `0` - All thresholds met ✅
- `1` - One or more thresholds failed ❌

### Manual Validation

```bash
# Generate coverage
npx nx test football-director-engine --coverage

# Check thresholds
node .github/scripts/check-coverage.js "football-director-engine" "coverage/libs/football-director-engine"

# View detailed report
open coverage/libs/football-director-engine/index.html
```

### Adjusting Thresholds

**File**: `.github/scripts/check-coverage.js`

```javascript
const THRESHOLDS = {
  global: {
    lines: 80,      // Change minimum line coverage
    branches: 70,   // Change minimum branch coverage
    functions: 80,  // Change minimum function coverage
    statements: 80, // Change minimum statement coverage
  },
  perFile: {
    lines: 60,      // Change per-file minimum
  },
};
```

**When to Adjust:**
- Achieving consistently higher coverage
- Legacy code with low coverage (temporary exception)
- Type definition files (exclude from coverage)

## PR Process

### Creating a Pull Request

1. **Push your branch**
   ```bash
   git push origin feature/your-feature
   ```

2. **Create PR on GitHub**
   - Click "New pull request"
   - Select your branch
   - Fill in description
   - Submit PR

3. **CI automatically runs**
   - All quality gates executed
   - Coverage validation performed
   - Results posted as checks

### During PR Review

#### Check CI Status

```
✅ Build, Test & Lint — Passed
   - Build: ✅ Passed
   - Lint: ✅ Passed
   - Test (engine): ✅ Passed (791 tests)
   - Coverage: ✅ Passed (93.21%)
   - Test (app): ✅ Passed
```

#### Review Coverage Comment

Look for the automated coverage comment:

```markdown
## 📊 Coverage Report

### football-director-engine
| Metric | Coverage | Status |
|--------|----------|--------|
| Lines | 93.21% | 🟢 |
| Branches | 83.15% | 🟢 |
| Functions | 94.85% | 🟢 |
```

#### Common Review Actions

**✅ All Green - Ready to Merge**
- All checks passed
- Coverage maintained or improved
- No blocking comments

**⚠️ Coverage Decreased**
- Review uncovered lines
- Add missing tests
- Re-run CI after fixes

**❌ Tests Failed**
- Review failure logs
- Fix failing tests locally
- Push fixes
- CI automatically re-runs

### After Merge

1. **Main CI runs**
   - Full validation on main branch
   - Coverage archived
   - Artifacts saved

2. **Auto-merge to release**
   - If main CI passes
   - Fast-forward merge only
   - Release branch stays in sync

3. **Coverage tracking**
   - Codecov tracks coverage trends
   - Historical data available
   - Coverage badges updated

## Troubleshooting

### CI Failures

#### Build Failure

**Error**: `Type error: Property 'X' does not exist on type 'Y'`

**Solution:**
```bash
# Run build locally
npx nx build <project-name>

# Fix type errors
# Push changes
git push
```

#### Lint Failure

**Error**: `ERROR: Unexpected console statement (no-console)`

**Solution:**
```bash
# Auto-fix lint issues
npx nx lint <project-name> --fix

# Commit fixes
git add .
git commit -m "fix: lint errors"
git push
```

#### Test Failure

**Error**: `FAIL src/lib/example.spec.ts > should work`

**Solution:**
```bash
# Run tests locally
npx nx test <project-name>

# Fix failing test
# Re-run to verify
npx nx test <project-name> -- example.spec.ts

# Push fix
git push
```

#### Coverage Failure

**Error**: `Lines coverage (78.5%) below threshold (80%)`

**Solution:**
```bash
# Generate coverage report
npx nx test football-director-engine --coverage

# View uncovered lines
open coverage/libs/football-director-engine/index.html

# Add tests for uncovered code
# Verify coverage
node .github/scripts/check-coverage.js "football-director-engine" "coverage/libs/football-director-engine"

# Push new tests
git push
```

### Performance Issues

#### Slow CI Runs

**Typical Duration**: 2-3 minutes

**If slower (>5 minutes):**

1. **Check npm cache**
   - Should show cache hit
   - If not, cache may be corrupted

2. **Check Nx cache**
   - Nx reset runs before lint
   - Should reuse build artifacts where possible

3. **Check test parallelization**
   - Vitest runs tests in parallel
   - Ensure no `--no-threads` flag

#### Timeout Errors

**Error**: `Error: Timeout of 120000ms exceeded`

**Solutions:**

1. **Increase test timeout**
   ```typescript
   it('long test', async () => {
     // test code
   }, { timeout: 300000 }); // 5 minutes
   ```

2. **Optimize slow tests**
   - Reduce test data size
   - Mock expensive operations
   - Split into multiple tests

### Artifact Access

#### Downloading Coverage Reports

1. Go to CI run on GitHub
2. Click "Summary"
3. Scroll to "Artifacts"
4. Download "coverage-reports"
5. Extract and view locally

#### Downloading Test Results

1. Same as above
2. Download "test-results"
3. Contains detailed test output

### PR Comment Not Appearing

**Possible Causes:**

1. **CI hasn't completed**
   - Wait for CI to finish
   - Comment posts after success

2. **PR from fork**
   - Fork PRs have limited permissions
   - May not post comments

3. **Workflow permissions**
   - Check repository settings
   - Ensure workflow has write access

## Best Practices

### Before Pushing

```bash
# 1. Run tests locally
npm test

# 2. Check coverage
npx nx test football-director-engine --coverage

# 3. Validate coverage
node .github/scripts/check-coverage.js "football-director-engine" "coverage/libs/football-director-engine"

# 4. Lint code
npx nx run-many -t lint --fix

# 5. Build
npx nx run-many -t build

# 6. If all pass, push
git push
```

### During Development

- **Run tests in watch mode**: `npx nx test <project> --watch`
- **Fix lint on save**: Configure your IDE
- **Check coverage frequently**: Don't wait for CI
- **Keep PRs small**: Easier to review and test

### After Merging

- **Monitor release branch**: Ensure auto-merge succeeded
- **Check Codecov**: View coverage trends
- **Review artifacts**: Download if needed for debugging

## Monitoring

### GitHub Actions Dashboard

- View all workflow runs
- Filter by branch, status, workflow
- Download logs for debugging

### Codecov Dashboard

- **URL**: https://codecov.io/gh/your-org/your-repo
- Track coverage over time
- Compare branches
- View file-level coverage

### Metrics to Track

- **Test count**: Should increase with new features
- **Coverage percentage**: Should stay above thresholds
- **CI duration**: Should stay under 5 minutes
- **Failure rate**: Should be low (<5%)
